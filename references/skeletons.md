# 骨架

| 类型 | 结构 | 长度 |
|---|---|---|
| 随拍 | 情绪或刚发生的事 → 具体怎么回事（带数字、带现场）→ 自己的反应或看法 → 一句收尾或一个问句 | 30～60 秒，100～250 字 |
| 观点 | 对象或行业 → 冲突事件 → 观点 → 证据（自己的事）→ 建议 | 45～90 秒 |
| 故事 | 结果 → 起因 → 困境 → 转机 → 回头看的体会 | 60～120 秒 |
| 晒过程 | 起因 → 关键步骤 → 转折 → 结果 | 45～90 秒 |
| 教程 | 见下 | 60～120 秒 |
| 商单 | 教程骨架 + 广告方硬性要求，见 sponsored.md | 按要求 |

## 随拍
- 不分点、不写"第一第二"、不埋产品、不写金句。
- 只给提纲式短稿，留出临场发挥的空间；保留本人的重复和磕巴，别修平。

## 教程
1. 结果前置（0～5 秒）：先给做完的样子或前后对比。
2. 为什么你也需要（一两句）。
3. 步骤：最多 3～4 步，每步一句话加一段录屏；关键指令和按钮名字上字幕。
4. 最容易踩的坑：一个就够，放在步骤中间。
5. 验证结果：回到开头的画面，证明做到了。
6. CTA：完整指令、链接、资料放评论区。

交付三栏脚本：

| 口播（一句一行） | 画面（录屏 / 人 / 截图） | 大字或字幕重点 |
|---|---|---|

外加一份"要录的素材清单"。

## 通用写法
- 全文只留一个核心主张，其他观点降成证据或例子。
- 把道理改成一件发生过的事；至少有一个只有本人知道的细节。
- 30 秒左右再抓一次注意力（一个数字、一个转折、一个画面）。
- 标出刺点：哪句让人点赞、评论、收藏。
- 产品在正文里最多轻提一次，说成"我现在在做的事"，不念价格。
